fetcher.js
    - export 1: fetchSubtitleFileList
    - export 2: searchSubtitleFile
    - export 3: fetchSubtitleText
    fetch tool: loggedFetch (core: fetchWithTimeout)

    - cụm xử lí tìm kiếm:
        parseSearchQuery: tách searchKey từ user thành obj {value, caseSensitive (boolean)}
            mỗi cụm key ngăn cách bằng dấu cách ngoài ngoặc kép là 1 token.
            mỗi cụm key ngăn cách bằng dấu "|" là 1 group.
            * Hướng dẫn cho end-user thuật toán tìm kiếm:
                mỗi cụm từ được ngăn cách bởi dấu cách (vd: `hello world` thì tìm "hello" và "world")
                nếu cụm từ nằm trong ngoặc kép (`"nice shot sir"`) thì tìm cả cụm "nice shot sir".
                sử dụng "#" thì sẽ có phân biệt hoa-thường (dùng cho tìm ID video)
                sử dụng "|" thì cho phép gộp kết quả tìm kiếm nhiều lần.
        foldText: Hàm chuyển đổi tiếng Việt có dấu thành không dấu để tìm kiếm.
            (tính năng tìm kiếm cả tiếng Việt có dấu và không dấu)
        editDistanceSubstring: hàm tính điểm theo khoảng cách Levenshtein giữa pattern (token đã fold) và tên file (đã fold)
        maxAllowedDistance: hàm quy định khoảng cách Levenshtein tối đa cho phép (mức độ liên quan giữa cú pháp và tên tệp)
        scoreSearchToken: thuật toán tính điểm và kiểm tra khớp chính xác/gần đúng cho từng token (trả về { score, exact })
        scorePhraseRuns: hàm tính điểm bonus (1000đ/từ gần đúng, có khoảng cách levenshtein cho phép)
        scoreSearchGroup: thuật toán tính tổng điểm nhóm token theo 3 mức (không khớp = 0, khớp 1 phần / na ná = 1xxx-4xxx, khớp chính xác 100% = >= 1_000_000)
        matchSubtitle: hàm tổng hợp điểm theo 1 cụm (group) các nhóm token
    - searchSubtitleFile: hàm lọc và sắp xếp tệp theo thuật toán của hàm matchSubtitle (scoreSearchGroup).
        Chú ý: ở đây chỉ tìm kiếm chỉ mục đã có sau khi chạy fetchSubtitleFileList.
    - fetchSubtitleText: hàm tải text của file sub từ fetchUrl
    - cụm tạo lập chỉ mục
        normalizeGDriveUrl: tiền xử lí link gdrive
        scanGDrive: xử lí quét và lấy dữ liệu thư mục gdrive
        normalizeGitHubUrl: tiền xử lí link github
        scanGitHub: xử lí quét và lấy dữ liệu thư mục github
    - fetchSubtitleFileList: hàm điều hướng chung

    * thông số thiết kế
        FETCH_TIMEOUT = 60000 (ms) - timeout cho fetchWithTimeout()
        SUBTITLE_SIZE_WARN = 10 * 1024 * 1024 (10MB) - cảnh báo file lớn
        VALID_FILE_SIGNATURE = ["[Script Info]", "[V4+ Styles]", "[Events]"] - chữ ký file .ass hợp lệ
        SEARCH_COMPLETE_BONUS = 1_000_000 - thưởng khi khớp chính xác 100% mọi token
        SEARCH_TOKEN_BAND = 1000 - mỗi token khớp cộng 1000 điểm

fetcher.js * (cấu trúc dữ liệu)
    1. fetchSubtitleFileList:
        input: array[string]             ( chấp nhận: array[string | {url: string}] )
        output: new sources = array[
            {
                url: string (input),                    // URL chuẩn hóa thư mục nguồn
                folderId: string (normalize),           // ID định danh (GDrive ID hoặc owner/repo/branch/path)
                sourceType: 'gdrive'|'github',          // loại nguồn
                name: string,                           // tên hiển thị thư mục (GDrive: og:title hoặc title, GitHub: repo/path, fallback: undefined_GDrive / undefined_GitHub)
                savedAt: number,                        // Date.now() lúc quét xong
                fileList: Array<FileEntry>              // danh sách file .ass (rỗng nếu lỗi)
            }
        ]
        FileEntry: {
            id: string,          // GDrive: fileId, GitHub: sha
            fileName: string,     // tên file gốc (đã decode HTML)
            fetchUrl: string,     // URL tải trực tiếp: GDrive = "https://docs.google.com/uc?export=download&id={id}", GitHub = item.download_url
            folderUrl: string,    // = source.url (để truy ngược thư mục cha)
            sourceType: 'gdrive'|'github',
            groupName: string     // = source.name (tên nhóm để hiển thị)
        }
    2. searchSubtitleFile:
        input: sources = output fetchSubtitleFileList()
        output: new candidates = array[
            FileEntry* {                // FileEntry nhưng bổ sung score
                id: string,
                fileName: string,
                fetchUrl: string,
                folderUrl: string,
                sourceType: 'gdrive'|'github',
                groupName: string,      // từ source.name
                score: number           // từ matchSubtitle(`${groupName} ${fileName}`, searchKey), >0 mới giữ
            }
        ]
    3. fetchSubtitleText:
        input: candidate: {id?: string, fileName?: string, fetchUrl?: string}
        output: text

fetcher.js * (pipeline)
    1. Đưa array[url: string] vào fetchSubtitleFileList, lấy sources lưu vào storage
    2. Khi end-user tìm kiếm thì đưa sources vào searchSubtitleFile, lấy candidates
    3. Khi end-user chọn tệp (candidate) thì gửi candidate cho fetchSubtitleText, lấy text đi xử lí tiếp

storage.js
    - export 1: addSource          — thêm nguồn folder (GitHub/GDrive) vào danh sách
    - export 2: getSourceList      — lấy danh sách nguồn (thuần đọc)
    - export 3: removeSource       — xóa nguồn theo id (UUID)
    - export 4: addSubData         — lưu cache sub (obj) theo videoId + cập nhật chỉ mục
    - export 5: getSubDataList     — lấy danh sách cache sub (phần nhẹ, đọc từ chỉ mục)
    - export 6: useSubData         — lấy toàn bộ subObj đã lưu (gồm parsedData)
    - export 7: removeSubData      — xóa cache sub theo videoId (+ xóa khỏi chỉ mục)
    - export 8: getConfig          — lấy config (toàn bộ dạng bản sao nông / 1 key)
    - export 9: setConfig          — cập nhật config 1 key
    - export 10: getRendererStat   — lấy dữ liệu render (fps, nps, dfps, subTitle)
    - export 11: setRendererStat   — cập nhật dữ liệu render (throttle ~4 lần/giây)

    * key trong chrome.storage.local:
        ASSCEE_sourceList           — array các nguồn: { url, folderName, ..., id (UUID), savedAt }
            (id là định danh ổn định dùng để xóa/so sánh trùng; savedAt chỉ là metadata.
             Nguồn cũ chưa có id được gán id tự động khi thêm nguồn mới)
        ASSCEE_subData_<videoId>    — subObj ĐẦY ĐỦ của 1 video (fileObj + parsedData + cachedAt),
            tách key riêng vì parsedData có thể nặng ~7MB
        ASSCEE_subIndex             — chỉ mục NHẸ của cache sub:
            { [videoId]: { ...fileObj, videoId, cachedId, cachedAt } }
            KHÔNG chứa parsedData → getSubDataList chỉ đọc key này, không tải key sub.
            Tự migrate 1 lần từ các key ASSCEE_subData_* khi key này chưa tồn tại.
        ASSCEE_config               — thiết đặt người dùng (chỉ string/number/boolean)
        ASSCEE_renderData           — dữ liệu render (fps, nps, dfps, subTitle)

    * quy ước chung:
        - storage.js là nơi DUY NHẤT ghi chrome.storage.local; module khác ghi qua các hàm export.
        - Lỗi do input/nghiệp vụ → result-object { success, data | error }; lỗi lập trình → throw.
        - Mọi read→modify→write chạy qua hàng đợi ghi PRIVATE trong storage.js (không export)
            để 2 lời gọi chồng nhau không ghi đè mất cập nhật.
        - setRendererStat giữ giá trị mới nhất trong bộ nhớ, chỉ flush tối đa ~4 lần/giây
            (queue đảm bảo không mất cập nhật, throttle đảm bảo ít lần ghi).
