            mỗi cụm key ngăn cách bằng dấu cách ngoài ngoặc kép là 1 token.
            mỗi cụm key ngăn cách bằng dấu "|" là 1 group.
            * Hướng dẫn cho end-user thuật toán tìm kiếm:
                mỗi cụm từ được ngăn cách bởi dấu cách (vd: `hello world` thì tìm "hello" và "world")

                sử dụng "#" thì sẽ có phân biệt hoa-thường (dùng cho tìm ID video)
                sử dụng "|" thì cho phép gộp kết quả tìm kiếm nhiều lần.
        foldText: Hàm chuyển đổi tiếng Việt có dấu thành không dấu để tìm kiếm.
            (tính năng tìm kiếm cả tiếng Việt có dấu và không dấu)
        editDistanceSubstring: hàm tính điểm theo khoảng cách Levenshtein giữa pattern (token đã fold) và tên file (đã fold)
        maxAllowedDistance: hàm quy định khoảng cách Levenshtein tối đa cho phép (mức độ liên quan giữa cú pháp và tên tệp)
        scoreSearchToken: thuật toán tính điểm và kiểm tra khớp chính xác/gần đúng cho từng token (trả về { score, exact })
        scorePhraseRuns: hàm tính điểm bonus (1000đ/từ gần đúng, có khoảng cách levenshtein cho phép)
        scoreSearchGroup: thuật toán tính tổng điểm nhóm token theo 3 mức (không khớp = 0, khớp 1 phần / na ná = 1xxx-4xxx, khớp chính xác 100% = >= 1_000_000)
        matchSubtitle: hàm tổng hợp điểm theo 1 cụm (group) các nhóm token
    - searchSubtitleFile: hàm lọc và sắp xếp tệp theo thuật toán của hàm matchSubtitle (scoreSearchGroup).

fetcher.js * (cấu trúc dữ liệu)
    1. fetchSubtitleFileList:
        input: array[string]             ( chấp nhận: array[string | {url: string}] )
        output: new sources = array[
            {
                url: string (input),                    // URL chuẩn hóa thư mục nguồn
                folderId: string (normalize),           // ID định danh (GDrive ID hoặc owner/repo/branch/path)
                sourceType: 'gdrive'|'github',          // loại nguồn
                name: string,                           // tên hiển thị thư mục (GDrive: og:title hoặc title, GitHub: repo/path, fallback: undefined_GDrive / undefined_GitHub)
                savedAt: number,                        // Date.now() lúc quét xong
                fileList: Array<FileEntry>              // danh sách file .ass (rỗng nếu lỗi)
            }
        ]
        FileEntry: {
            id: string,          // GDrive: fileId, GitHub: sha
            fileName: string,     // tên file gốc (đã decode HTML)
            fetchUrl: string,     // URL tải trực tiếp: GDrive = "https://docs.google.com/uc?export=download&id={id}", GitHub = item.download_url
            folderUrl: string,    // = source.url (để truy ngược thư mục cha)
            sourceType: 'gdrive'|'github',
            groupName: string     // = source.name (tên nhóm để hiển thị)
        }
    2. searchSubtitleFile:
        input: sources = output fetchSubtitleFileList()
        output: new candidates = array[
            FileEntry* {                // FileEntry nhưng bổ sung score
                id: string,
                fileName: string,
                fetchUrl: string,
                folderUrl: string,
                sourceType: 'gdrive'|'github',
                groupName: string,      // từ source.name
                score: number           // từ matchSubtitle(`${groupName} ${fileName}`, searchKey), >0 mới giữ
            }
        ]
    3. fetchSubtitleText:
        input: candidate: {id?: string, fileName?: string, fetchUrl?: string}
        output: text

fetcher.js * (pipeline)
    1. Đưa array[url: string] vào fetchSubtitleFileList, lấy sources lưu vào storage
    2. Khi end-user tìm kiếm thì đưa sources vào searchSubtitleFile, lấy candidates
    3. Khi end-user chọn tệp (candidate) thì gửi candidate cho fetchSubtitleText, lấy text đi xử lí tiếp

parser.js — xử lí tag override (kế hoạch + ĐÃ LÀM 27-29aug26)
    Mục tiêu: parser xử lí hết raw text → JS object để renderer dựng thành cây DOM.
    Phân loại tag (trong {...}) theo 4 nhóm:
    2.1 (Clip) Toàn cục, độc lập: áp 1 lần mỗi dòng, KHÔNG đổi kích thước khung chữ.
        - \clip / \iclip (cái CUỐI CÙNG có hiệu lực)
        - Chú ý: nếu có nhiều \clip lẫn \iclip (kể cả trong \t), thì \?clip cuối cùng quyết định
          loại clip (\clip hay \iclip) cho toàn bộ các tag \?clip trước đó.
    2.2 (Collision) Toàn cục, can thiệp: áp 1 lần mỗi dòng, CÓ đổi dữ liệu khung chữ.
        - \an: đổi tọa độ khung chữ (cái ĐẦU TIÊN có hiệu lực)
        - \org: vô hiệu hóa collision (cái ĐẦU TIÊN có hiệu lực)
        - \pos / \move: vừa đổi tọa độ khung vừa vô hiệu collision (cái ĐẦU TIÊN có hiệu lực)
        - \t: vô hiệu hóa collision
    2.3 (Decoration Local Tags) Cục bộ, độc lập: áp mỗi cụm từ (chia cụm từ thành các phần
        riêng biệt), KHÔNG đổi kích thước khung chữ.
        - các tag màu sắc, viền, bóng của chữ; \fa<x-y>; \fr<x-y-z>
    2.4 (Layout Local Tags) Cục bộ, can thiệp: áp mỗi cụm từ, CÓ đổi kích thước khung chữ.
        - cỡ chữ (\fs, \fsc), dấu cách & xuống dòng (\h, \N, \n), đổi font (\b, \i, \fn, \r), \fsp
    Thứ tự viết: (prereq: tokenizer + phân loại tag) → 2.4 → 2.3 → 2.2 → 2.1.
    Thứ tự xử lí:
        tokenizeLineText (token + clean) → baseFromTokens (tách các tag đơn trong tag token,
        ghép với text token kế tiếp thành mục base) → [bước SAU: phân loại/phân cấp 2.4→2.3→2.2→2.1].

    Tiền xử lí nội dung dòng (ĐÃ LÀM 27aug26 — 1 hàm duy nhất + tách segment):
    - tokenizeLineText(text) gộp cả 2 bước tokenize + clean (KHÔNG tách 2 hàm).
    - \h / \N / \n đứng NGOÀI tag → wrap thành {\h} / {\N} / {\n} riêng biệt, GIỮ NGUYÊN;
      renderer mới quyết định ngữ nghĩa (dấu cách / xuống dòng, theo WrapStyle / \q).
    - Tag {..}: bỏ comment thuần (không có '\'), strip phần trước '\' đầu, hợp nhất 2 tag liền nhau
      (}{) — TRỪ khi tag sau chứa karaoke (\k/\K/\kf/\ko) và TRỪ marker {\h}/{\N}/{\n}.
    - \{ \} giữ nguyên văn, unescape ở renderer (tầng cuối, khi không cần phân biệt text/tag nữa).
    - baseFromTokens(tokens): tách tag trong token → mục base (ĐÃ LÀM, tests/parser.test.mjs)
        + Segment model: mỗi tag token kết hợp với text token tạo thành 1 segment:
            segment = { tags: [...tag đơn raw nguyên văn], text }
            + Nhiều tag token LIỀN NHAU (tokenizer giữ riêng tag chứa karaoke) → gộp chung tags của 1 segment.
            + Text đứng trước mọi tag → segment { tags: [], text }.
            + Tag token cuối dòng (không còn text) → BỎ, không tạo segment (chốt 27aug26).
            + splitOverrideTags: tách theo '\' ở mức ngoặc ngoài cùng (đếm depth '()' nên \t(...)/\clip(...)
              không bị tách oan).
            + Chốt 27aug26: marker {\h}/{\N}/{\n} → flush NGAY thành segment RIÊNG tại đúng vị trí
              { tags: [marker], text: '' } (kể cả khi đứng cuối dòng); tag đang pending vẫn chờ text
              kế tiếp — marker không ăn mất pending. Renderer quét segment text rỗng có marker = chèn break.

    - Dữ liệu của popup chỉ đọc từ storage.
    - Đo chữ & layout (renderer): ĐÃ CHỐT dùng thuật toán cốt lõi của pretext
      (github.com/chenglou/pretext): chỉ lấy thuật toán lõi (prepare/đo segment một lần +
      layout thuần toán, kể cả rich-inline) đưa vào repo — KHÔNG bundle như dependency.
      Parser/bg vẫn thuần PlayRes, pretext chỉ dùng ở renderer. Chi tiết để ghi khi viết renderer.
